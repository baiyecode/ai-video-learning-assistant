## Problem Statement

营销文章（`frontend/content/articles/*.md`，4 篇）的正文和 frontmatter `description` 里硬编码了「$4.99/月」和「每日 3 次」，分布在 9 个源行、共 14 处字面出现。部署方通过 `APP_SUBSCRIPTION_MONTHLY_USD` / `APP_ANALYSIS_DAILY_QUOTA` 改价或改免费配额时，这些数字不会跟着变：

- 用户看到的价格页/结账页/个人中心是新价，文章却还在承诺旧价——同一站点两套说法，直接侵蚀转化信任；
- `description` 进 SEO meta 与 llms.txt 等 GEO 产物，AI 答案引擎抓到的是会说谎的摘要；
- 已合入的 #41 确立「单一价格/配额来源」：后端 `APP_*` 执行 + 前端 `VITE_*` 构建期镜像展示 + `/me/membership` 运行时载荷，但文章这条展示路完全绕开了该契约。

## Solution

文章模板化：Markdown 源里的价格与配额数字替换为构建期占位符，在文章加载的纯函数处沿既有 `VITE_*` 镜像链插值；客户端与预渲染共享同一份插值实现，改价时文章零改动。同时加最严格的构建期守卫——文章内容不允许出现任何未模板块的字面价格/配额模式，防止绕过模板手写数字。

## User Stories

1. 作为部署方，我改 `APP_SUBSCRIPTION_MONTHLY_USD` 重新构建后，希望所有文章的月价陈述自动变成新价，所以全站任何角落不再出现旧价格。
2. 作为部署方，我希望 compose 里同一对 `APP_*` 旋钮继续同时驱动执行（后端）与展示（含文章），所以调价的唯一入口保持不变、不需要记住第二处手改。
3. 作为潜在买家，我在文章里读到的价格和结账页一致，所以我对「$X.XX/月」的承诺有信任、更可能下单。
4. 作为已登录用户，我在个人中心看到的 `monthly_price_usd` 与文章陈述一致，所以我不会怀疑自己被不同价格两套话术对待。
5. 作为访客，我读到的免费配额陈述（每 Asia/Shanghai 自然日 N 次 Analysis）与后端实际强制的 Quota 一致，所以我规划升级前能算准免费额度。
6. 作为 SEO 抓取方，文章页面的 `<meta description>` 与正文数字一致，所以搜索摘要不会对站内其他页面说谎。
7. 作为 GEO/AI 答案引擎，我从 llms.txt 与预渲染 HTML 提取的价格与配额是当前的，所以生成的推荐答案不传播过期数字。
8. 作为内容维护者，我新增一篇带定价陈述的文章时只需要写占位符、不需要知道当前价格，所以新文章天然接入单一来源。
9. 作为内容维护者，如果我在文章里手写「$4.99/月」或「每日 3 次」这类字面数字，构建要失败并指出文件，所以漂移在合入前被机器拦住而不是上线后被动发现。
10. 作为维护者，如果 `VITE_` 参数被投毒或类型错误（小数配额、负价格），插值沿用既有的回退与拒绝逻辑，所以文章永远不会渲染「$NaN/月」。
11. 作为维护者，如果正文出现未知或未闭合的占位符，构建要失败，所以拼写错误不会把 `{{...}}` 原样漏到线上页面。
12. 作为 SSR/预渲染读者，我看到的文章 HTML 与客户端 hydration 渲染逐字一致，所以不产生 hydration 文本漂移告警。
13. 作为未来接手的开发者，我用一条 seam 就能断言「注入不同价 → 产物文本变化」，所以不需要起后端或浏览器即可验证本行为。
14. 作为 code review agent，审查文章相关改动时能依据「文章不得含字面定价」这条已编码的守卫，而不是靠人肉 grep。

## Implementation Decisions

- **插值位置**：文章集合的纯函数加载层（frontmatter 解析与校验所在的既有模块），对正文 body、frontmatter `title` 与 `description` 三个字段做占位符替换；`tags` 是字面标签，不做插值，出现占位符语法即构建失败（避免原始 token 进入 `article:tag`）。模块保持纯、无 DOM——客户端 bundle、预渲染 SSR、单测三者共享同一实现是既定架构约束（ADR：保留 SPA + 构建期预渲染），因此不允许引入只在一侧生效的渲染分支。
- **插值时机在长度校验之前**：`description` 的 70–160 字符校验作用于插值后的最终文本，SEO 描述以真实长度把关。
- **占位符词汇**（恰两个，Markdown 源中出现）：
  - `{{MONTHLY_PRICE_USD}}` → `$4.99/月` 形态（数值取两位小数，沿用现有文案样式）；
  - `{{DAILY_FREE_QUOTA}}` → `3`（整数）。
  改动 4 篇文章正文与 description 中的 9 处硬编码；中文措辞逐字不变，只把数字换成占位符（涉及「每日 3 次 Analysis」等短语的拆分方式见 Testing Decisions 的字面守卫口径）。
- **真相源**：只读既有的两个 billing 助手（月价构建期镜像、免费 Quota 构建期镜像），二者内部经统一的构建期 env 访问器解析（拒小数配额、拒非正价格、异常回退默认值）。不新增 env 键，不让文章模块直接读 env。
- **失败即构建失败**：未知/未闭合占位符 → 抛内容校验错误（沿用文章模块现有的构建失败模式，错误信息带文件名）；解析完仍残留字面价格/配额模式的正文同样拒绝。守卫范围包括 frontmatter title、description、正文和标签；孤立的 `}}` 是普通正文（代码块可能出现），只有未闭合的 `{{` 视为占位符错误。
- **不动的部分**：后端、`/me/membership` 载荷、Dockerfile ARG 默认值、compose 的 `APP_* → VITE_*` 接线、#41 确立的「载荷优先、构建镜像兜底」运行时契约全部保持原样——文章的兜底只能是构建镜像（构建期静态内容拿不到运行时载荷）。

## Testing Decisions

- 好测试只断外部行为：给定构建参数 → 产物文本；不断言插值函数内部结构。
- **内容模型单测**（既有文章解析测试的兄弟用例）：注入不同价/配额断言 title、description 与正文的插值结果；未知占位符、未闭合占位符、残留字面「\$数字.数字/月」「每日 数字 次」模式逐例断言构建错误；description 长度按插值后文本判定。
- **内容源守卫测试**：遍历 4 篇真实 Markdown 源，断言不含任何字面价格/配额模式（即守卫本身对现内容成立）。
- **预渲染产物测试**（既有 build-site 测试先例：注入测试价 → 断言产物文本与 JSON-LD Offer 同源一致）：扩展到文章页——注入与默认不同的价格后重新构建，断言文章 HTML 与 meta description 呈现新价。
- **SSR/客户端一致性**：既有「营销 shell 与预渲染逐字节一致」模式（jsdom 双渲染比较）作为先例，覆盖文章含插值文本的情形。
- **e2e**：沿用既有 Playwright 黄金路径注入改价断言可见文本的模式，可选扩展至文章页；非必须。

## Out of Scope

- 后端与 `/me/membership` 载荷的任何改动。
- 首页、价格页、FAQ、Terms 等非文章内容的改造——它们已经走镜像/载荷双路，本次只把文章接入同一契约。
- `VITE_*` 接线模式重构、新增 env 键。
- Search Console / 社交调试器发布手动项、Docker/nginx 运行时验证、并发 resolve 500——各自另案。
- 文章正文的其他文案润色或新增文章。
