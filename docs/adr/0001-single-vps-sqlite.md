# 单机部署与 SQLite 的容量边界

MVP 采用单台 2C4G VPS + Docker Compose 部署 FastAPI 与构建后的前端静态文件，数据库使用 SQLite（WAL 模式）。设计上限为 50 并发在线、单视频 2 小时/2GB、同时进行中的 Download 不超过 5 个。选择 SQLite 是因为没有独立数据库的运维与成本，代价是不能横向扩展写实例，超过容量时只能排队，未来扩容必须迁移数据库。

**考虑过的替代方案**：Postgres（更强的并发与扩展性，但增加运维面）；托管数据库（减少运维，但增加月度成本与网络依赖）。

**Consequences**：所有写操作限定在单实例；每日做文件级备份；视频文件只落本地磁盘，不引入对象存储。
